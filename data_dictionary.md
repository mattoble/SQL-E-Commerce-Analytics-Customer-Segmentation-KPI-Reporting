# Data Dictionary: ECommerceAnalytics

## 1. Base Tables

### Table: `gold.dim_customers`
**Description:** Dimension table containing demographic and profile information for all registered customers.
| Column Name | Data Type | Description | Classification |
| :--- | :--- | :--- | :--- |
| `customer_key` | INT | Unique identifier for each customer. | Primary Key |
| `customer_number` | VARCHAR(50) | Alternate business key/account number for the customer. | Dimension |
| `first_name` | VARCHAR(50) | Customer's given name. | Dimension |
| `last_name` | VARCHAR(50) | Customer's surname. | Dimension |
| `birthdate` | DATE | Customer's date of birth. | Dimension |
| `marital_status` | VARCHAR(50) | Current marital status (e.g., Single, Married). | Dimension |
| `gender` | VARCHAR(50) | Customer's gender. | Dimension |
| `country` | VARCHAR(50) | Customer's country of residence. | Dimension |

### Table: `gold.dim_products`
**Description:** Dimension table containing the product hierarchy and baseline manufacturing costs.
| Column Name | Data Type | Description | Classification |
| :--- | :--- | :--- | :--- |
| `product_key` | INT | Unique identifier for each product. | Primary Key |
| `product_name` | VARCHAR(100) | Full commercial name of the product. | Dimension |
| `category` | VARCHAR(50) | Top-level product grouping (e.g., Bikes, Accessories). | Dimension |
| `subcategory` | VARCHAR(50) | Secondary product grouping (e.g., Mountain Bikes). | Dimension |
| `cost` | DECIMAL(10,2) | Baseline manufacturing or procurement cost per unit. | Measure |

### Table: `gold.fact_sales`
**Description:** Core fact table recording all transactional sales data.
| Column Name | Data Type | Description | Classification |
| :--- | :--- | :--- | :--- |
| `order_number` | VARCHAR(50) | Unique identifier for a sales transaction. | Dimension |
| `product_key` | INT | Identifier linking to `dim_products`. | Foreign Key |
| `customer_key` | INT | Identifier linking to `dim_customers`. | Foreign Key |
| `order_date` | DATE | Date the transaction was completed. | Dimension |
| `sales_amount` | DECIMAL(18,2) | Total revenue generated by the line item. | Measure |
| `quantity` | INT | Number of units purchased in the line item. | Measure |
| `price` | DECIMAL(10,2) | Selling price per individual unit. | Measure |

## 2. Reporting Views (Calculated Logic)

### View: `gold.report_customers`
**Description:** 360-degree customer profile integrating demographics with lifetime transaction behavior.
* **`age_group`**: Classifies customer age into standard demographic brackets (e.g., 18-24, 25-34).
* **`customer_segment`**: 
  * `VIP`: 12+ months active lifespan AND >$5,000 total spend.
  * `Regular`: 12+ months active lifespan AND <=$5,000 total spend.
  * `New`: <12 months active lifespan.
* **`recency`**: Months elapsed since the customer's `last_order_date`.
* **`lifespan`**: Total months between the customer's first and last order.

### View: `gold.report_products`
**Description:** Consolidated product performance view aggregating sales and categorizing revenue generation.
* **`product_segment`**: 
  * `High-Performer`: Total generated sales > $50,000.
  * `Mid-Range`: Total generated sales between $10,000 and $50,000.
  * `Low-Performer`: Total generated sales < $10,000.
* **`avg_monthly_revenue`**: `total_sales` divided by product `lifespan` (months active).
